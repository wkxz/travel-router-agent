# 数据源调研：高德之外还能接什么（全部实测，2026-10-20）

> 结论先行：**不用再找"点评类"第三方 API 了 —— 高德自己的 POI 就带评分和人均。**
> 真正该补的是「天气 / 营业时间校验 / 路线时长 / 背景讲解」这四块，其中三块免费且已实测可用。

---

## 0. 最重要的发现：`extensions=all` 会返回评分、人均、营业时间

之前做 mall 项目时没开这个参数，只拿到名字和地址。开启后 `poi.biz_ext` 直接给：

```json
"biz_ext": {
  "rating": "4.7",
  "cost": "46.00",
  "open_time": "09:30-22:00",
  "opentime2": "周一至周日 09:30-22:00",
  "meal_ordering": "0"
}
```

### 实测覆盖率（王府井 1.5km / types=050000 / keywords=小吃 / 25 条）

| 字段 | 命中 | 覆盖率 |
|---|---|---|
| `rating` 评分 | 25 / 25 | **100%** |
| `cost` 人均 | 23 / 25 | 92% |
| `open_time` 营业时间 | 22 / 25 | 88% |

### 样例（同一批请求）

| 店名 | 评分 | 人均 | 营业时间 |
|---|---|---|---|
| 方砖厂69号炸酱面(南锣鼓巷店) | 4.7 | 46 | 09:30-22:00 |
| 门框胡同百年卤煮(新街口店) | **4.8** | 51 | 09:30-**02:00** |
| 陈记卤煮小肠(廊房二条店) | 4.7 | 34 | 09:00-20:00 |
| 四季民福烤鸭店(望京南湖东园店) | 4.7 | 161 | 10:30-21:30 |
| 和府捞面(北京市百货大楼店) | 4.3 | 39 | 10:00-21:30 |

### 这意味着什么

1. **"必吃推荐"不用人工兜底清单了** —— 排序函数可以直接用 `rating` + `cost` + 距离。
2. **排程可以做可行性校验** —— `门框胡同百年卤煮` 营业到 02:00，可以塞进夜宵档；
   `陈记卤煮` 20:00 关门，排到 21:00 就是错的。之前担心"推荐了关门的店"这个坑，现在能自动挡掉。
3. **人均可做预算控制** —— 用户说"人均 50 以内"，直接 `cost <= 50` 过滤。
4. **零额外成本** —— 同一个 Key、同一次请求，只是多个参数。

> 唯一代价：`extensions=all` 响应体变大（约 2-3 倍），对 Agent 的 token 消耗有影响。
> 处理方式：工具层只回传精简字段（name/rating/cost/open_time/distance），不要把原始 JSON 塞给模型。

## 1. 同 Key 就能用的「高德其他方向」接口（零成本，已实测）

大部分人只用了 `/place/text` 和 `/place/around`，其实同一个 Key 覆盖 12 个子服务。

| 能力 | 端点 | 实测 | 对本项目的用途 |
|---|---|---|---|
| **天气** | `/v3/weather/weatherInfo` | ✅ 200，朝阳区 3 天（小雨/晴/晴，13/14/15℃） | 雨天把户外景点换成室内；决定要不要带伞 |
| **行政区/城市编码** | `/v3/config/district` | ✅ 200，adcode 110105 + 下辖街道 | 把"朝阳区"转成天气接口要的 adcode |
| **公交路线** | `/v3/direction/transit/integrated` | ✅（本次请求返回空，因起终点太近） | 跨区移动的真实耗时 |
| **步行/驾车/骑行** | `/v3/direction/walking\|driving\|bicycling` | 之前已验证 | 景点间通勤时间 |
| **输入提示** | `/v3/assistant/inputtips` | 之前已验证 | 用户说"南锣"自动补全 |
| **地理编码/逆编码** | `/v3/geocode/geo\|regeo` | 之前已验证 | 地址 ↔ 坐标 |
| **静态地图** | `/v3/staticmap` | 未测 | 生成行程缩略图（前端用） |
| **IP 定位** | `/v3/ip` | 未测 | 用户没说城市时兜底 |

**天气接口的坑**：`city` 参数要的是 **adcode**（如 `110105`），不是城市名。
所以链路是：`地名 → /config/district 拿 adcode → /weather/weatherInfo 拿预报`。
两次请求，中间可以缓存 adcode。

## 2. 完全免费、免 Key 的外部接口（已实测）

| 服务 | 用途 | 实测结果 | 建议 |
|---|---|---|---|
| **Open-Meteo** | 逐小时天气 + 降水概率 | ✅ 200，北京 2 天逐小时 | **推荐**，比高德天气更细（有 `precipitation_probability`），可精确到"下午 3 点有雨" |
| **OSRM** | 路线规划 / 时长 / 距离 | ✅ 200，1392m / 120.7s | **备选**，只在想省高德 QPS 时用；国内数据质量不如高德 |
| **MyMemory** | 中英翻译（菜名） | ✅ 200，`Braised pork intestines` → `炖猪肠` | **推荐**，做"给外国朋友介绍必吃"或反向翻译 |
| **Nominatim** | OSM 地理编码 | ⚠️ 超时/空响应 | 不推荐，国内访问不稳 |
| **LibreTranslate** | 翻译 | ❌ 403（公共实例已限流） | 不推荐 |
| **Pexels** | 景点配图 | ❌ 401（必须 Key） | 想要配图再申请 |

## 3. 明确不要用的（实测被墙或不可靠）

| 服务 | 实测 | 结论 |
|---|---|---|
| `zh.wikipedia.org` | ❌ 000 超时 | **不可用** |
| `en.wikipedia.org` | ❌ 000 超时 | **不可用** |
| `commons.wikimedia.org` | ❌ 000 超时 | **不可用** |
| `www.wikidata.org` | ⚠️ 一次 200、一次 000 | **不稳定，不能做生产依赖** |
| `zh.wikivoyage.org` | ⚠️ API 200 但返回 93 字节空壳 | 不可靠 |

**关键判断**：EdgeOne 部署在腾讯云国内节点，出网环境和你本机一样。
所以「用 Wikipedia 给景点做背景讲解」这条路**在中国大陆服务器上走不通** —— 本地测通了线上也会挂。

> 替代方案：景点背景讲解**交给模型自己的知识**（LLM 本来就知道故宫是什么），
> 不需要外部 API。真正需要外部数据的只有「实时性信息」：天气、营业时间、距离、评分。

## 4. 餐饮口碑类 API 的现实情况（诚实结论）

| 平台 | 免费 API | 说明 |
|---|---|---|
| 大众点评 | ❌ 无公开 API | 只能爬，不合规且不稳定 |
| 美团 | ❌ 需企业资质 | 开放平台不对外 |
| 饿了么 | ❌ 需资质 | 同上 |
| Yelp Fusion | ⚠️ 5000 次/月免费 | 只有海外数据，国内城市基本空白 |
| Foursquare | ⚠️ 有免费层 | 国内数据稀疏 |

**所以**：国内的"必吃推荐"排序依据 = 高德 `rating` + `cost` + 距离 + 品类匹配度。
这已经是目前能拿到的最好数据，而且完全免费。不要再花时间找点评 API。

## 5. 最终推荐的数据源组合

### MVP 必接（全部零成本）

```
高德 /place/around   (extensions=all)  → 店名 + 坐标 + 评分 + 人均 + 营业时间 + 品类
高德 /place/text     (extensions=all)  → 关键词精确搜索（如"卤煮""豆汁"）
高德 /config/district                  → 地名 → adcode
高德 /weather/weatherInfo              → 3 天预报（决定室内/户外）
高德 /direction/{walking,driving}      → 景点间真实通勤时长
```

### v1.5 加分项

```
Open-Meteo  → 逐小时降水概率，做到"下午 4 点有雨，把景山换成国博"
MyMemory    → 菜名英译（给外国游客 / 让输出更有质感）
高德 /v3/staticmap → 行程路线缩略图
```

### 明确不做

```
Wikipedia / Wikidata / Wikimedia Commons  → 国内不可达
大众点评 / 美团 / 饿了么                   → 无公开免费 API
Yelp / Foursquare                        → 国内数据空白
LibreTranslate / Pexels                  → 403 / 401，需绕路
```

## 6. 落地要点（写代码时会踩的）

1. **`extensions=all` 必须显式传**，默认是 `base`，不传就拿不到 `biz_ext`。
2. **`biz_ext` 字段可能缺失**，`rating` 缺失的店要能降级排序（用距离 + 品类权重兜底），不能 `KeyError`。
3. **`open_time` 格式不统一**：有 `09:30-22:00`，也有 `07:00-09:00 10:00-22:00`（分段），
   还有 `opentime2` 带中文星期。解析要容错，解析失败就当"未知营业时间"，不要当"关门"。
4. **跨零点营业**（`09:30-02:00`）不能简单比较大小，要特殊处理。
5. **天气接口要两次请求**（district → weather），中间缓存 adcode，别每次都查。
6. **工具返回值必须精简**：高德原始 POI 单条 JSON 有 40+ 字段，25 条就上万 token。
   工具层只回传 6 个字段，其余丢掉。
